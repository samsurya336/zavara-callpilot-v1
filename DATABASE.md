# Zavara CallPilot MVP Database

This document describes the current Supabase/PostgreSQL schema for the hackathon MVP.

The MVP is account-owned. Users do not need an organisation, team, subscription, or payment setup before practising.

## Conventions

- Database names use `snake_case`; frontend/API models may expose camelCase equivalents.
- All IDs are UUIDs generated by PostgreSQL unless otherwise noted.
- Timestamps use `timestamptz` and default to `now()`.
- User-owned records reference `public.profiles.id`, which is created from `auth.users`.
- Most MVP feature tables use broad authenticated access for the hackathon; Knowledge Base is the exception and is owner-scoped.
- JSONB fields are intentionally flexible for the hackathon. Their expected contents are described below.

## Entity overview

```text
auth.users
    │
    └── profiles
          ├── knowledge ──┐
          │                └── challenge ── participant
          ├── call_session ──┐
          │                   └── call_session (Time Machine branch)
          ├── account_usage
          └── purchase_history ── package_plan
```

## Supabase Auth

### `auth.users`

Managed by Supabase Auth. Application code must not insert directly into this table.

| Column               | Type          | Details                                           |
| -------------------- | ------------- | ------------------------------------------------- |
| `id`                 | `uuid`        | Primary key. Referenced by `public.profiles.id`.  |
| `email`              | `text`        | Managed by Supabase Auth.                         |
| `raw_user_meta_data` | `jsonb`       | Includes signup metadata such as the user's name. |
| `created_at`         | `timestamptz` | Managed by Supabase Auth.                         |

The full structure is owned by Supabase and may contain additional provider-specific columns.

## Auth foundation

### `public.profiles`

One application profile per authenticated user. A trigger creates or synchronises this row when `auth.users` changes.

| Column       | Type          | Null | Default | Details                                      |
| ------------ | ------------- | ---: | ------- | -------------------------------------------- |
| `id`         | `uuid`        |   No | —       | Primary key; foreign key to `auth.users.id`. |
| `name`       | `text`        |   No | `''`    | Display name.                                |
| `email`      | `text`        |   No | `''`    | Synchronised from Auth.                      |
| `created_at` | `timestamptz` |   No | `now()` | Profile creation time.                       |

> Note: `email` is intentionally documented as the value stored in the current migration; it is synchronised from Auth metadata by the existing trigger.

## Knowledge Base

### `public.knowledge`

Stores one personal PDF knowledge entry. A user can have multiple entries, but each entry has one file.

| Column              | Type                          | Null | Default             | Details                                                                               |
| ------------------- | ----------------------------- | ---: | ------------------- | ------------------------------------------------------------------------------------- |
| `id`                | `uuid`                        |   No | `gen_random_uuid()` | Primary key.                                                                          |
| `created_by`        | `uuid`                        |   No | —                   | Owner; foreign key to `profiles.id`.                                                  |
| `title`             | `text`                        |   No | —                   | User-facing knowledge title.                                                          |
| `file_url`          | `text`                        |   No | —                   | Private Storage object path: `knowledge/<user-id>/<knowledge-id>/<file>`.              |
| `file_type`         | `text`                        |   No | —                   | Only `application/pdf`.                                                                |
| `file_size_bytes`   | `integer`                     |   No | —                   | Must be between 1 byte and 10 MiB (`10,485,760` bytes).                               |
| `file_meta`         | `jsonb`                       |   No | `{}`                | File name, MIME metadata, checksum, or other bounded metadata. Must be a JSON object. |
| `extraction_status` | `knowledge_extraction_status` |   No | `PROCESSING`        | `PROCESSING`, `READY`, or `FAILED`.                                                   |
| `extracted_text`    | `text`                        |  Yes | —                   | Extracted content. Maximum 2,000,000 bytes.                                           |
| `extraction_error`  | `text`                        |  Yes | —                   | Safe error description when extraction fails.                                         |
| `created_at`        | `timestamptz`                 |   No | `now()`             | Creation time.                                                                        |
| `updated_at`        | `timestamptz`                 |   No | `now()`             | Automatically updated by trigger.                                                     |

Only the owner can read or delete a knowledge entry. The extraction function writes status and content with the service role. Only `READY` entries can be attached to generated challenges.

Files are stored in the private `documents` bucket. Storage access is limited to the owner's `knowledge/<user-id>/...` path.

## Challenges Module

### `public.challenge`

Stores both seeded Open Challenges and user-specific Knowledge-based Challenges. A challenge can support either One-on-One or Boardroom practice.

| Column             | Type               | Null | Default             | Details                                                                                               |
| ------------------ | ------------------ | ---: | ------------------- | ----------------------------------------------------------------------------------------------------- |
| `id`               | `uuid`             |   No | `gen_random_uuid()` | Primary key.                                                                                          |
| `created_by`       | `uuid`             |  Yes | —                   | Null for seeded internal challenges; owner for generated challenges.                                  |
| `title`            | `text`             |   No | —                   | Challenge name.                                                                                       |
| `description`      | `text`             |   No | `''`                | Short scenario description.                                                                           |
| `category`         | `text`             |   No | `'General'`         | Sales skill category, such as Objection Handling.                                                     |
| `difficulty`       | `text`             |   No | —                   | `EASY`, `MEDIUM`, or `HARD`.                                                                          |
| `call_type`        | `call_type`        |   No | —                   | `ONE_ON_ONE` or `BOARDROOM`.                                                                          |
| `duration_minutes` | `integer`          |   No | —                   | Maximum duration; limited to 1–60 minutes.                                                            |
| `objective`        | `text`             |   No | —                   | What the user should achieve.                                                                         |
| `scenario`         | `text`             |   No | —                   | Meeting and buyer context.                                                                            |
| `product_context`  | `text`             |  Yes | —                   | Fictional or knowledge-derived product context.                                                       |
| `tags`             | `text[]`           |   No | `{}`                | Filtering/display tags.                                                                               |
| `is_active`        | `boolean`          |   No | `true`              | Whether users can currently start it.                                                                 |
| `source`           | `challenge_source` |   No | `INTERNAL`          | `INTERNAL` for Open Challenges; `KNOWLEDGE_BASE` for generated challenges.                            |
| `knowledge_id`     | `uuid`             |  Yes | —                   | Required for `KNOWLEDGE_BASE`; references the owner's `knowledge` entry.                              |
| `configs`          | `jsonb`            |   No | `{}`                | Starter prompt, scenario configuration, scoring settings, or other app config. Must be a JSON object. |
| `created_at`       | `timestamptz`      |   No | `now()`             | Creation time.                                                                                        |
| `updated_at`       | `timestamptz`      |   No | `now()`             | Automatically updated by trigger.                                                                     |

Constraints:

- `INTERNAL` challenges must have no `created_by` or `knowledge_id`.
- `KNOWLEDGE_BASE` challenges must have both `created_by` and `knowledge_id`.
- Generated challenges must reference a `READY` knowledge entry owned by the same user.
- A challenge does not store `mode`; the same challenge supports both `ASSIST` and `BATTLE`. Mode belongs to the call session.

| `communication_style` | `text`        |   No | —                   | Direct, detailed, reserved, etc.                               |
| `hidden_motivation`   | `text`        |   No | —                   | Private buyer motivation for the AI engine.                    |
| `objections`          | `jsonb`       |   No | `[]`                | Private potential objections; must be a JSON array.            |
| `decision_authority`  | `text`        |   No | —                   | Decision-maker, influencer, or evaluator.                      |
| `voice_configs`       | `jsonb`       |   No | `{}`                | Private provider/voice settings; must be a JSON object.        |
| `sort_order`          | `smallint`    |   No | `0`                 | Participant ordering within a challenge.                       |

### `public.participant_public` — view

Browser-safe view of participant data. It exposes only:

`id`, `challenge_id`, `name`, `designation`, `company`, `personality`, `communication_style`, `decision_authority`, and `sort_order`.

It does not expose `hidden_motivation`, `objections`, or `voice_configs`.

## Calls Module

### `public.call_session`

Stores every practice attempt. A Time Machine attempt is a new row and never overwrites its parent session.

| Column                | Type            | Null | Default             | Details                                                                                            |
| --------------------- | --------------- | ---: | ------------------- | -------------------------------------------------------------------------------------------------- |
| `id`                  | `uuid`          |   No | `gen_random_uuid()` | Primary key.                                                                                       |
| `user_id`             | `uuid`          |   No | —                   | Session owner; foreign key to `profiles.id`.                                                       |
| `challenge_id`        | `uuid`          |   No | —                   | Foreign key to `challenge.id`.                                                                     |
| `status`              | `call_status`   |   No | `CREATED`           | `CREATED`, `ACTIVE`, `COMPLETED`, `FAILED`, or `CANCELLED`.                                        |
| `mode`                | `call_mode`     |   No | —                   | `ASSIST` or `BATTLE`.                                                                              |
| `parent_session_id`   | `uuid`          |  Yes | —                   | Parent session for a Time Machine branch. Null for an original call.                               |
| `branch_from_turn_id` | `text`          |  Yes | —                   | Selected user-answer turn ID for a branch.                                                         |
| `challenge_snapshot`  | `jsonb`         |   No | `{}`                | Snapshot of challenge/personas/knowledge context used by this call.                                |
| `settings`            | `jsonb`         |   No | `{}`                | Runtime settings such as consent, call configuration, or provider options.                         |
| `transcript`          | `jsonb`         |   No | `[]`                | Ordered transcript turns. Recommended fields include turn ID, speaker, text, order, and timestamp. |
| `report`              | `jsonb`         |  Yes | —                   | Post-call report generated for this session only.                                                  |
| `report_status`       | `report_status` |   No | `NOT_REQUESTED`     | `NOT_REQUESTED`, `PROCESSING`, `READY`, or `FAILED`.                                               |
| `provider_session_id` | `text`          |  Yes | —                   | ElevenLabs or other provider session identifier.                                                   |
| `recording_url`       | `text`          |  Yes | —                   | Optional recording reference. Recording is not required for the MVP.                               |
| `started_at`          | `timestamptz`   |  Yes | —                   | Actual call start time.                                                                            |
| `ended_at`            | `timestamptz`   |  Yes | —                   | Actual call end time.                                                                              |
| `duration_seconds`    | `integer`       |  Yes | —                   | Non-negative measured duration.                                                                    |
| `usage`               | `jsonb`         |   No | `{}`                | Provider consumption, reserved minutes, billable seconds, or usage metadata.                       |
| `metadata`            | `jsonb`         |   No | `{}`                | Non-sensitive operational metadata.                                                                |
| `created_at`          | `timestamptz`   |   No | `now()`             | Session creation time.                                                                             |
| `updated_at`          | `timestamptz`   |   No | `now()`             | Automatically updated by trigger.                                                                  |

Constraints and indexes:

- A branch must have both `parent_session_id` and `branch_from_turn_id`.
- An original call must have neither field.
- The parent session must belong to the same user.
- Only one session per user can have `status = 'ACTIVE'`.
- The original session and all branches are separately readable and reportable.

### `public.purchase_package(package_id)`

Atomic demo purchase operation:

1. Finds an active package.
2. Adds its minutes to `account_usage.available_minutes`.
3. Inserts a row into `purchase_history`.

A real payment webhook should call equivalent trusted logic after payment confirmation. This function keeps the hackathon purchase flow simple.

## Access rules

- Most MVP feature tables grant broad CRUD access to authenticated users for fast hackathon development.
- Knowledge rows and `documents/knowledge/<user-id>/...` objects are owner-scoped with RLS/storage policies; browsers cannot update extraction fields directly.
- `participant_public` remains available for components that only need visible persona fields, but the base `participant` table is also readable.
- Other `documents` objects use the existing broad policy; Knowledge Base objects use the owner-scoped path policy above.
- This is intentionally not production security. Do not use this access model for real customer or confidential product data.

## Seed data

The seed file creates:

- `The Price Negotiator` — One-on-One, medium difficulty.
- `The Executive Boardroom` — Boardroom, hard difficulty.
- One CFO persona for the first challenge.
- CEO, CTO, and CFO personas for the Boardroom challenge.
- Starter, Focused, and Builder minute packages for the purchase demo.

## Deliberately deferred

The MVP does not include subscriptions or recurring billing. It only purchases fixed minute packages and adds their minutes to the account balance.
